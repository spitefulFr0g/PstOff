# Writer repair checkpoint

The rebuilt engine emits v23 Unicode PSTs with 512-byte pages, permutative
encoding, no password, fresh indexes, rebuilt heaps/tables/subnodes and allocation
maps regenerated by the unmodified pinned Microsoft reader. Non-final heap pages
are padded to 8176 bytes; the oversized-heap and 40,000-byte attachment regressions
remain passing. Conversion currently requires `Split::Off` and no exclusions.

The writer now prepares source-backed Item properties before creating output.
Both Item PC emission and Q16 contents rebuilding consume that same plan. Q12
adds only a missing, nonzero, signed-range FILETIME from agreeing same-Item cache
observations. Q15 adds only missing members of an agreeing, binary XID/PCL pair;
existing members must agree before a partner is added. Validation includes bounded
XIDs, complete SizedXids, strictly increasing unique namespaces, matching LocalId
lengths and coverage of the paired key. These checks do not establish server
history. Each addition records its property, Item, source table IDs and reason.
Existing timestamp properties win even when their type differs.

Cache preparation validates heap maps, column bounds/widths/overlap/presence-bit
ownership, mandatory row identity descriptors/cells, recursive row indexes and
exact row/index identity/counts. Each contents row must resolve to an indexed Item
and ordinary/associated tables must belong to its folder. Q15 cells cannot alias
structural allocations. Tables exposing either pair column must provide both
valid members. A search table exposing neither column is not a pair observation.
Tables with no timestamp column do not supply timestamp observations. Missing
source observations remain unpromoted. Invalid/conflicting relevant observations
abort before output creation, with an error naming the policy/Item where available;
this conservative checkpoint does not yet accumulate unresolved policy diagnostics
in a successful Conversion report.

Q16 uses exact typed Item properties. Q17 removes only the unmatched `66280014`
cell, and required schema descriptors never introduce default cell values. GUID
TC cells use HNID storage. Essential store policy and temporary-file ownership
remain as documented in the original checkpoint; source hashing retains its
read-only source handle. The spike implementation is reference only, not copied.
